버튼을 눌러 패킷이 지나가는 길을 한 칸씩 따라가 보세요.내 Mac에서 출발한 SSH 요청이 서버에 닿고 응답이 돌아오기까지 7단계예요.

2. 문을 지키는 세 겹의 잠금

잠금어디서무엇을 보나다른 사람이 시도하면
① 라우팅rtb-public이 서브넷에 인터넷 길(0.0.0.0/0 → igw)이 있나public 서브넷까지는 길이 있음. private 서브넷에는 길 자체가 없음
② 보안 그룹web-sg보낸 사람 IP가 내 IP/32인가, 포트가 22인가여기서 차단. 응답 없이 시간 초과(timeout)
③ 키 인증EC2의 sshd개인 키(.pem)로 만든 서명이 서버의 공개 키와 맞나내 IP에서 오더라도 키가 없으면 Permission denied (publickey)

NACL은 기본값(전체 허용)이라 지금은 아무것도 막지 않아요. 보안 그룹은 상태를 기억하기(stateful) 때문에, 들어온 요청의 응답은 아웃바운드 규칙과 상관없이 자동으로 나가요.

4. 다음 단계

F

서버 기본 세팅

패키지를 업데이트하고 스왑 2GB를 만들어요. 메모리가 1GB뿐이라 Next.js 빌드 전에 꼭 필요해요.

sudo dnf update -y
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile swap swap defaults 0 0' | sudo tee -a /etc/fstab
free -h
G

VPC 흐름 로그 → 차단 기록 보기

VPC → aws-study-vpc → 플로우 로그 → 생성. 필터 거부(REJECT), 대상 CloudWatch Logs, 보존 1주. 휴대폰 핫스팟처럼 다른 IP에서 ssh를 시도한 뒤 기록이 남는지 확인해요.

H

RDS MySQL (프라이빗 서브넷)

프리 티어 템플릿 · db.t3.micro · 20GB · 자동 확장 끄기 · 퍼블릭 액세스 아니요 · aws-study-vpc · 보안 그룹은 db-sg만.

I

EC2 → RDS 접속 확인

EC2에 MySQL 클라이언트를 설치하고 RDS 엔드포인트로 접속해요. 이게 되면 "게이트웨이를 거쳐 DB로" 구조가 완성돼요.
