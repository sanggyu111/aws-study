AWS 계정 준비

콘솔에 로그인할 수 있는 계정과 안전장치(MFA)를 만들어요.

aws.amazon.com → 무료로 시작하기
  1. 이메일, 계정 이름, 카드 정보, 전화 인증을 입력하고 무료 플랜을 고릅니다.
  2. 로그인한 뒤 오른쪽 위 계정 이름 → 보안 자격 증명 → MFA 할당에서 인증 앱(Google Authenticator 등)을 연결합니다.
  3. (권장) IAM에서 평소에 쓸 사용자를 하나 만들고, 그 사용자로 로그인합니다. 로그인 화면에 계정 ID 12자리 + 사용자 이름 + 암호를 넣어요.
성공 확인콘솔 홈 화면이 보이고, 오른쪽 위에 계정 이름이 나와요.
주의
  • 무료 플랜은 6개월이 지나거나 크레딧을 다 쓰면 계정이 닫혀요. 닫힌 계정의 이메일로는 다시 가입할 수 없어서, Gmail이라면 이름+aws@gmail.com처럼 플러스 주소를 써요.
  • 로그인할 때 칸을 비워 두고 누르면 "인증 실패"가 떠요. 루트 사용자는 이메일로, IAM 사용자는 계정 ID로 로그인해요.
💡 꿀팁: 루트 계정은 금고 열쇠, 매일 쓰는 건 IAM
  • 루트 사용자는 결제·계정 설정처럼 루트만 할 수 있는 일에만 쓰고, MFA를 걸어 둔 뒤 넣어 두세요.
  • 실제 작업은 IAM 사용자로 하고, 실무처럼 맡은 일별로 권한을 나눠 보세요. 어떤 작업에 어떤 권한이 필요한지 직접 부딪혀 봐야 IAM이 이해돼요.

  • 권한이 모자라면 … is not authorized to perform: ec2:RunInstances 같은 오류가 떠요. 오류에서 어떤 권한이 빠졌는지 읽는 것도 공부예요.

  • 사람이 쓰는 건 사용자, 서비스가 쓰는 건 역할(Role)이에요. 예: 흐름 로그가 CloudWatch에 기록할 때 쓰는 권한은 역할이에요.

서버 기본 세팅 (swap 2GB)

메모리 1GB로는 Next.js 빌드가 죽을 수 있어서, 디스크를 여유 메모리로 빌려 써요.

SSH로 접속한 터미널에서 한 줄씩 복사해서 붙여 넣으세요 (직접 타이핑하면 오타가 나기 쉬워요).

sudo dnf update -y
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile swap swap defaults 0 0' | sudo tee -a /etc/fstab
free -h
성공 확인free -h 결과의 Swap 줄 total이 2.0Gi예요.
주의Swap이 0B면 swapon을 빠뜨렸거나 fstab에 오타(dfaults 등)가 있는 거예요. cat /etc/fstab로 확인해서 고친 뒤 sudo swapon -a를 실행해요.

EC2에서 DB 접속 확인

"서버를 거쳐야만 DB에 닿는다"를 직접 확인해요.

EC2에 SSH로 접속한 터미널에서 실행해요. 암호를 물으면 H단계에서 정한 암호를 입력해요 (화면에 글자가 안 보이는 게 정상).

sudo dnf install -y mariadb105
mysql -h RDS엔드포인트 -u admin -p

MySQL [(none)]>가 나오면 이어서:

SHOW DATABASES;
USE studydb;
CREATE TABLE hello (id INT PRIMARY KEY, msg VARCHAR(50));
INSERT INTO hello VALUES (1, 'from ec2');
SELECT * FROM hello;
exit
성공 확인표에 1 | from ec2가 나와요.
주의Mac에서 바로 DB에 접속하면 안 되는 게 정상이에요. 그게 이 과제의 목표예요. EC2에서도 접속이 멈춰 있으면 db-sg 인바운드 소스가 web-sg인지, EC2에 web-sg가 붙어 있는지 확인하세요.

Next.js 배포 (GitHub → EC2)

내 프론트엔드를 내 서버에서 띄우고, Nginx가 80번으로 받아 넘겨 줘요.

준비: next.config에 output: "standalone"이 있는 Next.js 저장소. 아래는 Node 24 + pnpm 프로젝트 기준이에요 (package.json의 engines와 packageManager를 확인하세요).

① 도구 설치

sudo dnf install -y git nginx
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install 24
corepack enable
npm install -g pm2

② 코드 받기 · 빌드

git clone https://github.com/내계정/저장소.git
cd 저장소/앱폴더
pnpm install --frozen-lockfile
pnpm build
cp -r public .next/standalone/
cp -r .next/static .next/standalone/.next/

③ pm2로 계속 켜 두기

PORT=3000 HOSTNAME=127.0.0.1 pm2 start .next/standalone/server.js --name web
pm2 save
pm2 startup

pm2 startup이 출력한 sudo env PATH=… 줄을 복사해 실행하면, 서버를 재시작해도 앱이 자동으로 켜져요.

④ Nginx: 80 → 3000 연결

sudo tee /etc/nginx/conf.d/next.conf >/dev/null <<'CONF'
server {
  listen 80;
  server_name _;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection 'upgrade';
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
CONF
sudo nginx -t
sudo systemctl enable --now nginx
성공 확인Mac 브라우저에서 http://퍼블릭IP를 열면 내 Next.js 화면이 나와요. (https가 아니라 http예요.) 터미널에서 curl -I http://퍼블릭IP를 하면 Server: nginx와 X-Powered-By: Next.js가 보여요.
주의
  • public과 .next/static을 복사하지 않으면 화면은 뜨지만 CSS·이미지가 깨져요.
  • 3000번 포트는 보안 그룹에 열지 않아요. 바깥에서는 80번(Nginx)만 들어와요.
  • 빌드 중 Killed가 나오면 F단계 swap이 켜져 있는지 확인하세요.

마무리: 끄기와 지우기

크레딧이 새지 않게, 안 쓸 때는 끄고 과제가 끝나면 지워요.

① 잠깐 쉴 때: 중지

  1. RDS → 데이터베이스 → aws-study-db → 작업 → 일시적으로 중지 (7일 뒤 자동으로 다시 켜져요)
  2. EC2 → 인스턴스 → aws-study-web → 인스턴스 상태 → 인스턴스 중지 (종료는 삭제이니 누르지 않기)
  3. 다시 켜면 퍼블릭 IP가 바뀌어요. 새 IP로 SSH·브라우저 접속하세요.

② 과제가 끝나면: 삭제 (안쪽부터 바깥 순서)

  1. RDS aws-study-db 삭제 (최종 스냅샷 만들지 않기, 자동 백업 보존 안 함)
  2. VPC → 흐름 로그 삭제 → CloudWatch 로그 그룹 aws-study-flowlogs 삭제
  3. EC2 인스턴스 종료
  4. RDS 서브넷 그룹 → 보안 그룹 db-sg → web-sg 순서로 삭제 (db-sg가 web-sg를 참조하고 있어서)
  5. VPC aws-study-vpc 삭제 (서브넷·라우팅 테이블·IGW가 함께 지워짐)
  6. EC2 → 키 페어 aws-study-key 삭제, Mac의 .pem 파일도 정리

③ 다음에 다시 시작할 때 (중지만 해 둔 경우)

  1. IAM 사용자로 로그인하고, 오른쪽 위 리전이 서울인지 확인해요.
  2. RDS → aws-study-db → 작업 → 시작. 7일이 지나서 이미 자동으로 켜져 있을 수도 있어요.
  3. EC2 → aws-study-web → 인스턴스 상태 → 인스턴스 시작 → 실행 중, 상태 검사 3/3 통과까지 기다려요.
  4. 새 퍼블릭 IP를 복사해요. 지난번 IP와 달라요.
  5. 다른 장소나 와이파이라면 web-sg 인바운드 22·80의 소스를 다시 내 IP로 바꿔 저장해요. SSH가 멈춰 있으면 대부분 이 문제예요.
  6. 새 IP로 접속하고 상태를 확인해요 (새 주소라서 yes를 한 번 더 물어요).
ssh -i ~/.ssh/aws-study-key.pem ec2-user@새퍼블릭IP
free -h                         # Swap 2.0Gi
pm2 list                        # web 이 online
sudo systemctl status nginx     # active (running)

pm2 list가 비어 있으면 pm2 resurrect를 실행하고, 그래도 없으면 J단계 ③의 pm2 start를 다시 실행해요. 그다음 브라우저에서 http://새퍼블릭IP를 열어 확인하고, 끝나면 ①처럼 다시 중지해요.
