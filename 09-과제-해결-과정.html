VPC 만들기 완료

서버는 인터넷 쪽에, DB는 숨은 쪽에 둘 나만의 네트워크

한 일

  1. "VPC 등" 마법사: AZ 2, public 2, private 2, NAT 없음, 엔드포인트 없음
  2. 첫 시도(awsstudy)는 생성하지 않고 다시 aws-study-vpc로 생성
  3. 기본 VPC(172.31.0.0/16) 화면을 보고 헷갈림 → 과제용 VPC와 구분
  4. 리소스 맵에 라우팅 테이블이 4개 보임 → 기본(main) 라우팅 테이블 확인

Q. 내가 얘기한 목표를 수행할 수 있는 설정이야? (기본 VPC 화면)

핵심 키워드

VPC · CIDR
AWS 안에 만든 나만의 네트워크예요. 10.0.0.0/16은 이 안에서 쓸 사설 주소 범위예요.
기본 VPC
AWS가 처음부터 만들어 둔 VPC(172.31.0.0/16)예요. 서브넷이 모두 퍼블릭이라 DB를 숨길 수 없어요. 지우지 말고 그대로 둬요.
퍼블릭 / 프라이빗 서브넷
라우팅 테이블에 0.0.0.0/0 → igw 경로가 있으면 퍼블릭, 없으면 프라이빗이에요. 이름이 아니라 경로가 결정해요.
인터넷 게이트웨이 (IGW)
VPC와 인터넷 사이의 대문이에요. 공인 IP와 사설 IP를 서로 바꿔 줘요. 요금은 없어요.
라우팅 테이블
"이 목적지로 가려면 어디로 보낼지" 적은 표예요. 서브넷마다 하나씩 연결돼요.
기본(main) 라우팅 테이블
VPC를 만들면 자동으로 생기는 이름 없는 예비 테이블이에요. 연결된 서브넷이 없고, 지울 수도 없고, 무료예요.
NAT 게이트웨이
프라이빗 서브넷이 인터넷으로 나가게 해 주는 장치예요. 켜 두기만 해도 시간당 요금이 나가서 이번에는 만들지 않았어요.
S3 게이트웨이 엔드포인트
첫 시도에서 기본값으로 생겼던 것이에요. S3로 가는 전용 길이고 무료예요.

보안 그룹 2개 완료

"나만 들어오기"와 "DB는 서버만"을 정하는 방화벽

한 일

  1. web-sg: SSH 22, HTTP 80 → 소스 내 IP
  2. db-sg: MYSQL/Aurora 3306 → 소스 web-sg
  3. 두 그룹 모두 VPC ID가 vpc-0123456789abcdef0인지 확인 (db-sg 설명 오타 daabase는 동작에 영향 없음)

핵심 키워드

보안 그룹
EC2·RDS 같은 자원에 붙이는 방화벽이에요. 허용 규칙만 적고, 적지 않은 건 모두 막혀요.
Stateful (상태 기억)
들어온 요청의 응답은 아웃바운드 규칙과 상관없이 자동으로 나가요. 그래서 db-sg 아웃바운드는 비워도 돼요.
내 IP /32
지금 내 공유기의 공인 IP 딱 하나만이라는 뜻이에요. 와이파이를 바꾸면 IP가 달라져서 SSH가 막힐 수 있어요.
보안 그룹 참조
소스를 IP 대신 web-sg로 정하면, "web-sg를 단 자원만" 허용돼요. 서버 IP가 바뀌어도 규칙이 계속 맞아요.
NACL
서브넷 단위 방화벽이에요. 상태를 기억하지 않아서(stateless) 응답 포트까지 직접 열어야 해요. 이번에는 기본값(전체 허용) 그대로 뒀어요.

핵심 키워드

AMI
서버에 깔 운영체제 이미지예요. Amazon Linux 2023의 기본 사용자는 ec2-user예요.
인스턴스 유형 t3.micro
2 vCPU · 1GB 메모리. 새 계정의 프리 티어 대상이에요.
크레딧 사양 표준
t3의 기본값은 "무제한"이라 CPU를 많이 쓰면 추가 요금이 나올 수 있어요. 표준이면 느려질 뿐 돈은 더 나가지 않아요.
키 페어
비밀번호 대신 쓰는 열쇠 한 쌍이에요. 공개 키(자물쇠)는 서버에, 개인 키(.pem)는 내 Mac에 있어요. .pem 파일은 다시 받을 수 없어요.
chmod 400
"나만 읽기, 남은 아무것도 못 함" 권한이에요. 권한이 열려 있으면 ssh가 키를 거부해요.
퍼블릭 vs 프라이빗 IP
Mac에서는 퍼블릭(43.203…)으로 접속해요. 10.0.x.x는 VPC 안에서만 쓰는 주소예요. 인스턴스를 중지했다 켜면 퍼블릭 IP가 바뀌어요.
ssh -i 키 사용자@주소
-i는 identity file, 즉 신분증 파일이에요. 문장으로 읽으면 "이 열쇠를 들고, 이 주소의 이 사용자로 암호화된 통로를 열어 줘"예요.
< > 는 빼기
설명서의 꺾쇠는 "여기에 값을 넣으세요"라는 표시예요. 터미널에서 <는 "파일에서 읽기"라는 특수 기호라 그대로 넣으면 오류가 나요.

내가 했던 질문

Q. 2.0Gi가 안 보이는데?

핵심 키워드

스왑 (swap)
메모리가 모자랄 때 디스크 일부를 메모리처럼 빌려 쓰는 공간이에요. 느리지만 빌드가 Killed로 죽는 걸 막아 줘요.
mkswap vs swapon
mkswap은 스왑으로 쓸 준비, swapon은 실제로 켜기예요. 준비만 하면 0B로 나와요.

복사해서 붙여넣기
명령어는 직접 타이핑하지 말고 복사해서 붙여 넣기. 이번 오타가 남긴 교훈이에요.

핵심 키워드

VPC 흐름 로그
VPC 안 네트워크 인터페이스를 오간 연결을 한 줄씩 기록해요. 필터를 REJECT로 두면 "막힌 시도"만 남아요.
레코드 읽는 법
… 출발IP 도착IP 출발포트 도착포트 6 패킷 바이트 시작 끝 REJECT OK. 프로토콜 6은 TCP예요.
로그 그룹 · 보존 기간
로그를 담는 통이에요. 기본값 "만기 없음"이면 계속 쌓이니까 1주로 줄였어요.
인터넷 배경 소음
공개 IP라면 몇 분 안에 스캐너와 봇이 모든 포트를 두드려요. IPv4는 약 43억 개뿐이라 전체를 훑는 데 오래 걸리지 않아요. 정상이고, 다 막히고 있다는 증거예요.
패킷 1개 · 40~60바이트
"똑똑" 한 번 두드리고 대답이 없으면 떠난 흔적이에요. 연결은 되지 않았어요.
UTC
로그 시간은 세계 표준시예요. 한국 시간은 +9시간(04:29Z = 13:29)이고, 화면에서 로컬 시간대로 바꿀 수 있어요.
로그 분석 (Logs Insights)
쿼리로 "누가 몇 번 시도했나"를 표로 볼 수 있어요. 예: stats count(*) by srcAddr, dstPort

핵심 키워드

DB 서브넷 그룹
RDS가 놓일 수 있는 서브넷 목록이에요. 자동으로 만들게 두면 public 서브넷까지 들어가서, 미리 private만 넣었어요.
퍼블릭 액세스 아니요
DB에 공인 IP를 주지 않아요. 인터넷에서는 DB 주소가 보이지도 않아요.
InnoDB vs MyISAM
MySQL의 저장 방식이에요. MySQL 5.5부터 기본값은 InnoDB(트랜잭션, 충돌 복구)이고, 따로 적지 않으면 InnoDB라서 경고는 무시해도 돼요.
자체 관리 자격 증명
Secrets Manager를 고르면 매달 별도 요금이 나가요. 암호는 직접 정하고 메모해요.
스토리지 자동 조정
용량이 모자라면 알아서 늘어나는 기능이에요. 무료 범위를 넘을 수 있어서 껐어요.
RDS 중지 7일

EC2 → RDS 접속 확인 완료

"게이트웨이(서버)를 거쳐야만 DB에 닿는다"를 확인

한 일

  1. EC2에 mariadb105 클라이언트 설치
  2. mysql -h <엔드포인트> -u admin -p 접속
  3. SHOW DATABASES → studydb 확인 → hello 테이블 생성, INSERT, SELECT → from ec2 출력

핵심 키워드

RDS 엔드포인트
DB의 주소 이름(…rds.amazonaws.com)이에요. VPC 안에서는 사설 IP로 바뀌어요.
MySQL 클라이언트
DB에 말을 거는 프로그램이에요. MariaDB 클라이언트로도 MySQL에 접속할 수 있어요.
점프 서버 구조
인터넷 → EC2 → DB 순서로만 닿아요. Mac에서 바로 접속이 안 되는 게 정상이에요. 필요하면 SSH 터널(ssh -L)로 EC2를 거쳐 접속해요.

핵심 키워드

engines · Node 24
package.json에 정해 둔 Node 버전이에요. nvm으로 정확히 24를 설치했어요.
pnpm · corepack
이 프로젝트의 패키지 매니저예요. corepack이 packageManager에 적힌 버전을 자동으로 맞춰 줘요.
output: standalone
실행에 필요한 파일만 모아 줘요. 단 정적 파일(CSS·JS)과 public은 직접 복사해야 화면이 깨지지 않아요.
pm2
앱을 뒤에서 계속 켜 두고, 죽으면 다시 살려 주는 관리자예요. SSH 창을 닫아도 서버가 꺼지지 않아요.
Nginx 리버스 프록시
80번으로 받은 요청을 서버 안쪽 3000번으로 넘겨 줘요. 3000번은 인터넷에 열지 않아요.
응답 헤더로 확인하기
Server: nginx + X-Powered-By: Next.js → Vercel이 아니라 내 EC2가 보낸 페이지예요.
Vercel vs EC2
둘 다 GitHub 코드를 가져다 쓰는 별개의 복사본이에요. 하나를 지워도 다른 쪽과 저장소에는 영향이 없어요.
2FA 복구 코드
인증 앱을 잃었을 때 쓰는 일회용 코드예요. 2FA를 켤 때 받아서 안전한 곳에 보관해요.

마무리: 정리와 비용 관리 지금

과제를 끝내고 크레딧이 새지 않게 하기

할 일

  1. 안 쓸 때는 EC2 중지 (다시 켜면 퍼블릭 IP가 바뀜)
  2. 과제 제출이 끝나면 RDS 삭제 (최종 스냅샷 만들지 않기)
  3. 흐름 로그 → 로그 그룹 → EC2 → VPC 순서로 삭제
  4. Billing → 프리 티어 / 크레딧 화면에서 사용량 확인
  5. 다음 확장: Spring 백엔드를 붙이면 "브라우저 → Nginx → Next.js → Spring → RDS"

핵심 키워드

중지 vs 종료
중지는 꺼 두기(디스크 요금은 조금 나감), 종료는 삭제예요. 종료하면 되돌릴 수 없어요.
삭제 순서
다른 자원이 쓰고 있는 것은 지워지지 않아요. 안쪽(RDS, EC2)부터 바깥(VPC) 순서로 지워요.
