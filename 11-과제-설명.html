AWS 기초 과제

EC2 웹서버 하나를 "나만 들어오고, 침입 시도는 기록되고, DB는 숨겨진" 상태로 만들고 그 위에 Next.js를 띄우기

과제 목표 5가지

1
EC2 서버

AWS에 리눅스 가상 서버 한 대를 켠다.

2
나만 들어오는 방화벽

내 IP와 내 키를 가진 사람만 서버에 접속할 수 있다.

3
남의 접속 시도 기록

다른 사람이 들어오려다 막힌 흔적을 로그로 남긴다.

4
게이트웨이를 거치는 DB

DB의 인바운드·아웃바운드 규칙을 정해, 서버를 거쳐야만 DB에 닿게 한다.

5
Next.js 서버

내 Next.js 프로젝트를 EC2에서 실행해 브라우저로 연다.

완성하면 이런 모습

주황 숫자는 위 목표 번호예요. 내 Mac에서 출발한 요청만 IGW와 보안 그룹을 지나 서버에 닿고, DB는 그 서버 뒤에 숨어 있어요.

목표별로 무엇을 쓰고, 어떻게 확인하나

목표사용하는 것다 됐는지 확인하는 방법
1 EC2 서버VPC(public 서브넷) · EC2 t3.micro · Amazon Linux 2023인스턴스 상태 실행 중, 퍼블릭 IP가 있음
2 나만 접속보안 그룹 web-sg(22·80 ← 내 IP /32) + 키 페어(.pem)내 Mac에서 ssh -i 키 ec2-user@IP 성공, 키 없이 또는 다른 IP에서는 실패
3 시도 기록VPC 흐름 로그(필터 REJECT) → CloudWatch 로그 그룹로그 그룹에 모르는 IP의 REJECT 줄이 쌓임, Logs Insights로 IP별 횟수 조회
4 숨은 DBRDS MySQL · private 서브넷 · 퍼블릭 액세스 아니요 · db-sg(3306 ← web-sg만)EC2에서는 mysql 접속·조회 성공, Mac에서 직접은 접속 불가
5 Next.jsNode + pnpm 빌드(standalone) · pm2 · Nginx(80 → 3000)브라우저 http://퍼블릭IP에 내 페이지, 응답 헤더 Server: nginx · X-Powered-By: Next.js

조건: 무료 플랜, 최소 비용

새 계정의 무료 플랜 크레딧 안에서 끝내는 것이 조건이에요. 그래서 일부러 쓰지 않는 것이 있어요.

✓ 쓰는 것

  • EC2 t3.micro: 프리 티어 대상, 크레딧 사양 "표준"
  • RDS db.t3.micro: 프리 티어 템플릿, 단일 AZ, 20GB
  • 흐름 로그 REJECT만: 로그 양 최소, 보존 1주
  • IGW · 보안 그룹 · 라우팅 테이블: 무료
  • Budgets 제로 지출 예산: 요금이 생기면 바로 알림

✕ 쓰지 않는 것

  • NAT 게이트웨이: 켜 두기만 해도 시간당 요금
  • 탄력적 IP · 로드 밸런서: 서버 1대에는 필요 없음, 요금 발생
  • Multi-AZ · 스토리지 자동 조정: 무료 범위를 넘김
  • Secrets Manager: 비밀 1개당 매달 요금
  • Vercel 등 외부 배포: 과제는 "내 EC2"에서 띄우는 것

시작 전에 필요한 것

  • Mac과 터미널 (Windows라면 PowerShell의 ssh)
  • AWS 가입용 이메일과 해외 결제 가능한 카드
  • 스마트폰 인증 앱 (MFA용)
  • GitHub에 올린 Next.js 프로젝트 (next.config에 output: "standalone")
  • 3~4시간 (RDS 생성 대기 10~15분 포함)

제출 전 최종 점검

  • EC2 화면: 인스턴스 유형 t3.micro, 보안 그룹 web-sg, 인바운드 소스가 내IP/32
  • 터미널: SSH 접속 화면 ([ec2-user@ip-10-0-…]$)
  • CloudWatch: 흐름 로그 REJECT 기록 또는 Logs Insights 결과 표
  • RDS 화면: 퍼블릭 액세스 "아니요", 보안 그룹 db-sg, db-sg 인바운드 소스 = web-sg
  • EC2에서 실행한 SELECT * FROM hello; 결과
  • 브라우저: http://퍼블릭IP로 열린 Next.js 페이지
  • 끝나면 EC2·RDS 중지 또는 삭제 (RDS는 중지 7일 뒤 자동으로 켜짐)
